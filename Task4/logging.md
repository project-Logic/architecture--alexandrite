### Мотивация

Логирование необходимо для отслеживания ключевых событий в системе, выявления и устранения ошибок, а также для аудита действий пользователей и компонентов. Это позволит:
- Быстро находить и устранять сбои и аномалии.
- Повышать прозрачность работы системы.
- Улучшать качество поддержки и сопровождения.
- Снижать риски потери данных и инцидентов безопасности.

#### Технические и бизнес-метрики:
1. Время реакции на инциденты.
2. Количество успешно обработанных заказов.
3. Количество ошибок и сбоев.
4. Время восстановления после сбоя.
5. Уровень удовлетворенности клиентов.

### Необходимые логи (уровень INFO):
- Изменение статуса заказа (время, id покупателя, номер заказа, старый и новый статус).
- Создание заказа (время, id покупателя, номер заказа, параметры заказа).
- Ошибки при обработке заказа (время, id заказа, описание ошибки).
- Вход пользователя в систему (время, id пользователя, ip-адрес).
- Вызовы внешних API (время, endpoint, параметры запроса, результат).
- События очередей RabbitMQ (время, тип события, id сообщения, статус обработки).

### Использование других уровней логирования:
- DEBUG — для детальной отладки в тестовых окружениях.
- WARN — для потенциально опасных ситуаций (например, превышение лимитов).
- ERROR — для критических ошибок, влияющих на бизнес-процессы.

### Приоритет внедрения логирования и трейсинга:
В первую очередь — Shop API, MES API, CRM API, RabbitMQ. Именно здесь чаще всего возникают проблемы с заказами и интеграциями.

### Предлагаемое решение
- Использовать централизованную систему логирования (например, ELK Stack: Elasticsearch, Logstash, Kibana).
- Внедрить логирование в ключевые сервисы (Shop API, MES API, CRM API, RabbitMQ).
- Настроить парсинг и хранение логов в отдельных индексах по системам.
- Настроить алерты на аномалии (например, резкий рост ошибок или заказов).
- Настроить автоматическое удаление логов старше 90 дней.
- Ограничить доступ к логам только для сотрудников с ролью «Поддержка» и «DevOps».
- Исключить из логов чувствительные данные (например, пароли, полные ФИО, платежные данные).

### Политика безопасности
- Доступ к логам — только по аутентификации и авторизации.
- Шифрование логов при передаче и хранении.
- Аудит доступа к логам.

### Политика хранения
- Хранение логов в отдельных индексах по системам.
- Срок хранения — 90 дней.
- Размер — не более 100 ГБ на систему, далее — автоматическое удаление старых данных.

### Система анализа логов
- Настроить алерты на превышение пороговых значений ошибок и аномалий.
- Внедрить поиск аномалий (например, резкий рост заказов или ошибок).
- Использовать Kibana для визуализации и анализа логов.
